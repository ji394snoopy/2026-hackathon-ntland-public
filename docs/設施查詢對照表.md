## 輸入模型

前端傳其中一種，後端統一處理：

| 輸入 | 形式 | 對應 |
|---|---|---|
| 1 個點 | `{ lat, lng, radius? }` | radius 模式（預設半徑 500m） |
| 4 個點 | `polygon: [[lng,lat] x4]` | polygon 模式 |

> `infra/lambda/facilities/input.ts` 的 `parseArea()` **已完整支援這兩種輸入**，輸入層不需改。

## 資料源策略（混合，依變動頻率分流）

不做「全部匯入」也不做「全部即時」，按資料性質分三類：

| 類別 | 策略 | 原因 |
|---|---|---|
| **A 靜態/低頻** — 站點、路線、門牌 | 匯入 PostGIS | 幾乎不變，離線可跑、支援 polygon |
| **B 政府即時 API** — NLSC 環域、排水、土質、風速 | **即時呼叫 + 快取表（TTL）** | 政府端會更新；快取兼顧新鮮度與離線保險 |
| **C 動態但無官方 API** — 百貨/金融/娛樂等 POI | OSM 匯入 PostGIS | OSM 本就是快照，定期重匯即可 |

**快取表設計（B 類）**

- key = 座標網格（lat/lng 取小數第 3 位，約 100m）+ 半徑 + 類別
- TTL 依資料性質：NLSC 設施 7 天、風速 30 天、土質/排水 90 天
- 命中回快取；未命中才打政府 API 並寫回
- 實作：DynamoDB 一張表，或本機 PostGIS 一張 `api_cache` 表

**查詢層對前端統一**：前端只呼叫 facilities API，內部依 category 決定走 PostGIS 或即時 API，前端無感。

> **已實作**：`infra/lambda/facilities/` 已同時整合三個來源到一份 `facilities[]`：
> PostGIS 站點、PostGIS `pois`(OSM)、以及 **NLSC 環域 API 即時呼叫**（`nlsc.ts`，含
> 殯葬/加油站/醫療/文教，每類 8 秒 timeout、單類失敗容錯）。環境變數
> `FACILITIES_INCLUDE_NLSC=off` 可關掉 NLSC 走純 DB（離線 demo）。
> B 類的「快取層（TTL）」尚未實作 — 目前 NLSC 是每次即時打；風速/土質/排水仍在 cli 各自即時。

### NLSC 環域 API 實測結論（已打過 dis/bus/med/edu）

API 格式：`.../MarkBufferAnlys/{code}/{lon}/{lat}/{radius}`，**只吃座標+半徑，不接受縣市參數**。
「限制新北市」= 用新北市座標 + 縮小半徑控制資料量（半徑跨區界時會撈到鄰區）。

| code | 粒度 | marktype 樣本 | 判定 |
|---|---|---|---|
| `dis` 鄰避 | 實質只 3 類 | `9960203` 加油站、`9350200` 公墓、`9930203` 納骨堂 | ✅ 僅殯葬/加油站；**變電所/電塔/瓦斯槽/垃圾場/焚化爐經補測確認不涵蓋 → 走 OSM** |
| `bus` 工商 | **粗（全 `corporation`）** | 電器行/蛋行/髮型坊/拉麵店 | ❌ 是公司登記戶，非業態分類，**第 6 類不可用，改走 OSM** |
| `med` 醫療 | 好（數字代碼） | `9930101` 醫院、`9930102` 衛生所、`9930301` 托育、`9930302` 養護 | ✅ 可用 |
| `edu` 文教 | 好（數字代碼） | `9920102` 高中、`9920103` 國小、`9920105` 幼兒園、`9920201` 圖書館 | ✅ 可用 |

**重點調整**：
1. **殯葬改用 NLSC `dis`**（已證實含公墓/納骨堂），可取代 `juan/publicCemetery` 靜態爬蟲
2. **工商活動（第 6 類）確定走 OSM** — NLSC `bus` 是公司登記，太碎且無業態分類
3. **變電所/電塔/瓦斯槽/垃圾場/焚化爐確定走 OSM** — 補測三個已知點（八里焚化廠正上方、林口電廠旁、板橋多變電所市區），`dis` 半徑內只回加油站與公墓，證實這幾類**不在 NLSC 涵蓋範圍**。NLSC「鄰避設施」實質＝殯葬＋加油站

## OSM 匯入（C 類）— 實際採用做法

> **已實作**：沒有裝 osm2pgsql、沒下載整包台灣 `.pbf`。改用 **Overpass API 以新北市
> 行政邊界過濾**，只抓需要的 tag 類別，產出小份 GeoJSON，再走既有 `load-geojson.mjs`
> 灌進 PostGIS 的 `pois` 表（與其他圖層同一條路徑）。目前快照 7996 筆、18 類（每次重跑
> `fetch-osm.mjs` 都會依當下的 OSM 內容變動）。

**產生 + 匯入：**

```bash
# 1) 產生 GeoJSON 快照（打 Overpass → assets/osm/ntpc-pois.geojson）
node infra/local/import/fetch-osm.mjs

# 2) 灌進本機 PostGIS 的 pois 表（容器需先啟動）
infra/local/import/import.sh pois
```

- 分類 ↔ OSM tag 的對應定義在 `infra/local/import/fetch-osm.mjs` 的 `CATEGORY_SELECTORS`
- `pois` 表：`category` / `name` / `props`(jsonb) / `geom`(Point 4326)，GiST + category 索引
- `facilities/query.ts` 已把 `pois` 併入回傳（帶中文 `kind` + `category`）

**檔案：**

| 檔 | 作用 |
|---|---|
| `infra/local/import/fetch-osm.mjs` | Overpass 抓取 → 帶 category 的 GeoJSON |
| `infra/local/import/sql/20-pois.sql` | 建 `pois` 表 + 索引 |
| `infra/local/import/import.sh`（`pois` target） | 灌 GeoJSON 進 `pois` |
| `infra/lambda/facilities/query.ts` | 查詢層併入 `pois`（`POI_KIND_ZH` 對應中文） |

### 方式一：Overpass API（即時查詢的原理，備查）

```typescript
async function queryOsmOverpass(lat: number, lng: number, radiusM: number) {
  const query = `
    [out:json][timeout:25];
    (
      node["amenity"="bank"](around:${radiusM},${lat},${lng});
      node["shop"="department_store"](around:${radiusM},${lat},${lng});
      way["shop"="department_store"](around:${radiusM},${lat},${lng});
    );
    out center tags;
  `;
  const res = await fetch("https://overpass-api.de/api/interpreter", {
    method: "POST",
    body: "data=" + encodeURIComponent(query),
  });
  const data = await res.json();
  return data.elements.map((el: any) => ({
    name: el.tags?.name ?? null,
    kind: el.tags?.amenity ?? el.tags?.shop,
    lat: el.lat ?? el.center?.lat,
    lng: el.lon ?? el.center?.lon,
  }));
}
```

- 優點：零匯入、立刻能跑，跟 cli「打 API」模式一致
- 缺點：速率限制、斷網即掛、polygon 用 `poly:` 有座標順序（`lat lon`）陷阱

### 方式二：osm2pgsql 匯入 PostGIS（離線、可 polygon，建議）

```bash
# 下載台灣 OSM 快照
wget https://download.geofabrik.de/asia/taiwan-latest.osm.pbf

# 匯入本機 PostGIS（產生 planet_osm_point / planet_osm_polygon / planet_osm_line）
osm2pgsql -H localhost -P 5433 -d gis -U postgres \
  --create --slim --hstore -G taiwan-latest.osm.pbf
```

匯入後查詢跟現有 `facilities/query.ts` 同一套：

```sql
SELECT name,
       tags->'shop' AS shop,
       tags->'amenity' AS amenity,
       ST_X(ST_Transform(way, 4326)) AS lon,
       ST_Y(ST_Transform(way, 4326)) AS lat
FROM planet_osm_point
WHERE (tags->'amenity' = 'bank' OR tags->'shop' = 'department_store')
  AND ST_DWithin(way::geography, ST_MakePoint($1,$2)::geography, $3);
```

- 優點：離線、統一走 PostGIS、polygon 天然支援
- 缺點：需跑一次匯入（台灣檔幾百 MB，約十幾分鐘）

**建議**：demo 用方式二匯入；驗證某分類 tag 是否正確時先用方式一 Overpass 試打。
